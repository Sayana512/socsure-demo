# SOCSure · Team Vigil · SIH 2026

Interactive demonstration of SOC supervisory assessment, using precomputed synthetic results. The intended full application runs locally, without cloud AI APIs.

## Publish to GitHub Pages — no local build required

1. Extract this package to a NEW folder, separate from your working offline prototype.
2. Sign in to GitHub and create a public repository named `socsure-demo`. Select **Add a README file** so the `main` branch exists.
3. Open **Code → Add file → Upload files**.
4. Open the extracted `socsure-github-pages` folder. Drag its CONTENTS into GitHub, including `docs`, `src`, `public`, `package.json`, `package-lock.json`, `vite.config.js`, `index.html`, `test-demo.mjs` and this `README.md`. Do not upload the outer folder itself or the unopened ZIP. Do not upload your local `.venv`, `node_modules` or real SOC data.
5. Commit to `main`. If you choose a new branch, merge its pull request into `main` before continuing.
6. Confirm the repository contains `docs/index.html`, `docs/assets/`, `docs/demo-snapshot.json` and `docs/SOCSure-Offline-Prototype.zip`.
7. Open **Settings → Pages → Build and deployment**.
8. Choose **Deploy from a branch**, select **main** and **/docs**, then **Save**.
9. Open **Actions** and wait for the **pages build and deployment** run to succeed. The published address will appear under **Settings → Pages**. For the suggested repository name it will normally be `https://YOUR-USERNAME.github.io/socsure-demo/`.
10. Open that address in an incognito/private window. Test navigation, a finding's source records, a browser-only decision and the offline download before putting the link in your PPT.

If Pages has not published, check the Actions logs and verify that the files are on `main`, with `docs` at the repository root. Do not select `/(root)` as the publishing folder. A public repository allows use of GitHub Pages with GitHub Free, subject to account/organization policies.

## What works in this showcase

- All eight dashboard pages; Data Upload explains the offline-only ingestion workflow.
- CSE, period, severity, type and confidence filters.
- Historical/peer comparisons, charts, workflow variants, source evidence and scores.
- Diverse review budgets of 10, 20 or 50 items.
- Examiner demo decisions, notes and decision trail stored ONLY in the visitor's browser.
- Review-pack and audit JSON exports, synthetic-data download, and full offline-project download.

## What is not live Python analysis

The precomputed snapshot was generated by the original Pandas/scikit-learn pipeline. GitHub Pages does not run FastAPI, Python models or SQLite. New evidence upload and threshold reanalysis require the downloadable offline project. Rule thresholds are read-only in this showcase. Accuracy metrics remain explicitly unmeasured. Browser-only decisions are demonstrations, not durable institutional audit records, and can disappear if browser storage is cleared.

Use only synthetic data here. Published static files are downloadable by visitors. No real submissions, credentials, personal notes or existing database are included. Review decisions are not shared between judges and do not modify the published snapshot.

## Optional source editing

Node 22.13+ is required only to modify and rebuild this demonstration:

```
npm ci
npm run dev
npm run build
node test-demo.mjs
```

After source changes, rebuild and commit the updated `docs` folder; GitHub publishes that folder. Changes to `src` alone do not change the website. Keep the `public` synthetic snapshot and offline ZIP when rebuilding; Vite copies them into `docs`.

The bundled offline ZIP includes the chart-navigation fix, backend, Python dependencies list, synthetic evidence, tests and setup instructions. It creates its local SQLite database on first use and requires Python 3.12. It includes a prebuilt frontend, so Node is not required to run the offline app.
